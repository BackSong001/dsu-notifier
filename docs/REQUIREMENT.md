# 요구사항

## 기능 요구사항

### FR-01 게시판 수집

시스템은 `docs/dsu_url.md`에 정의된 6개 게시판을 수집해야 한다.

### FR-02 공지 필드

공지마다 다음 필드를 처리해야 한다.

- 게시판 코드
- 게시판명
- 공지 번호
- 제목
- 작성자
- 등록일
- 조회수
- 상세 URL
- 고정 공지 여부
- 고정 공지 상태(`importance_status`: `true` 또는 `failed`)
- 최초 수집 시각
- 마지막 확인 시각

상세 URL의 `idx`를 원본 식별자로 사용한다. 고정 공지는 목록의 번호가 없을 수 있으므로 번호만으로 식별하지 않는다.
번호가 없는 고정 공지는 `number = null`로 저장한다. `is_notice`는 해당 수집 시점에 고정 공지인지 나타내고, `importance_status`는 고정 공지의 추적 상태를 나타낸다.

고정 공지가 이전 수집에는 있었지만 최신 첫 페이지에 없으면 기존 행의 `importance_status`를 `failed`로 변경한다. 최신 첫 페이지에서 다시 확인되면 `true`로 변경한다. 새 고정 공지는 `true`로 저장한다. 일반 공지에는 `importance_status = null`을 사용한다.

### FR-03 정기 수집

서버는 10분마다 수집 작업을 실행해야 한다. 각 실행은 최신 목록을 가져와 새 공지를 판별하고 고정 공지 상태를 갱신해야 한다. 테스트 환경의 Cron은 1분 주기로 실행한다.

### FR-04 중복 방지

같은 게시판의 같은 `idx`는 하나의 공지로만 저장해야 한다. 새 공지가 아닌 재수집은 공지 행과 알림 outbox를 다시 저장하지 않는다. 고정 공지 노출 상태가 실제로 바뀌는 경우에만 해당 상태를 갱신한다.

### FR-05 알림

새 공지가 저장되면 기존에 알림이 활성화된 등록 디바이스에 푸시해야 한다. 같은 공지와 디바이스 조합은 한 번만 발송한다. 앱의 `알람설정` 화면에는 사용자가 알림을 켠 게시판을 카드로 표시한다. 게시판 제목 옆 종 버튼으로 해당 게시판의 새 공지 알림을 변경한다. 일반 공지 카드의 별표는 공지 저장 기능이며 푸시 구독과 별개다. 고정 공지 카드에는 별표를 표시하지 않는다. 두 설정은 디바이스에 연결해 서버에 저장하며 앱을 다시 실행해도 복원한다.

### FR-06 디바이스 등록

앱은 로그인 없이 설치별 UUID, 별도 무작위 인증 비밀값과 FCM 토큰으로 등록·갱신한다. 비밀값은 기기에만 저장하고 서버에는 SHA-256 해시만 저장한다. 토큰 갱신은 설치 ID와 설정을 유지한다.

### FR-07 알림 설정

앱은 게시판별 알림 활성화 상태를 저장하고 서버에 반영해야 한다. 공지 카드의 저장 상태도 공지별로 저장하고 `저장된 공지` 메뉴에서 복원해야 한다.

### FR-08 앱 목록 갱신

- 앱 실행 시 현재 게시판의 첫 페이지(최대 19건)를 조회한다.
- 게시판 전환 시 목록을 새로 조회하고 첫 페이지와 목록 최상단으로 초기화한다.
- 목록은 당겨서 새로고침할 수 있어야 한다.
- foreground FCM 수신 시 현재 목록을 자동 갱신하고 새 공지 알림을 표시한다.
- 메뉴 전환 시 현재 화면의 목록을 다시 조회한다.

### FR-09 실패 처리

수집 실패, 파싱 실패, 알림 발송 실패를 구분해 기록해야 한다. 수집 실패 시 기존 공지를 삭제하지 않는다.

## 제약사항

- 대상 페이지는 현재 정적 HTML 목록으로 확인되었으므로 서버리스 HTTP 요청과 HTML 파서로 처리한다.
- 사이트 HTML 구조 변경 시 수집기가 실패할 수 있다.
- robots.txt와 사이트 운영 정책을 준수한다.
- Google OAuth는 요구하지 않는다.

### FR-10 설정 및 정책 공개

메뉴의 설정에서 개인정보처리방침, 서비스 이용약관, 데이터 삭제 및 권리 행사, 오픈소스 라이선스를 확인한다. 정책 본문은 오프라인으로 읽을 수 있어야 하며 앱 외부에는 로그인 없이 읽는 공개 URL을 제공한다. 앱과 공개 정책의 원본을 일치시킨다. 운영자와 문의 이메일, 설치 ID만 포함한 데이터 삭제 요청 복사 기능을 제공한다. 실제 데이터 삭제는 설치 소유 확인 후 운영자가 처리하며 기기 비활성화 또는 알림 끄기와 구분한다. 앱과 스토어에는 대학·정부의 공식 앱이 아닌 개인 개발 앱임을 명시한다.
