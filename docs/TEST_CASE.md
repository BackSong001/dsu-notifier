# 테스트 케이스

## 수집

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| TC-SCR-001 | 6개 게시판의 정상 HTML 수집 | 각 게시판의 목록이 파싱된다 |
| TC-SCR-002 | 번호가 있는 일반 공지 파싱 | 번호, 제목, 작성자, 날짜, 조회수, URL이 저장된다 |
| TC-SCR-003 | 번호가 없는 고정 공지 파싱 | `is_notice=true`, `source_idx`로 식별된다 |
| TC-SCR-004 | 상대 상세 URL 파싱 | 절대 URL로 저장된다 |
| TC-SCR-005 | 동일 공지를 재수집 | 공지 행이 추가되지 않는다 |
| TC-SCR-006 | HTML 구조가 깨진 응답 | 해당 실행을 실패 처리하고 기존 데이터는 유지한다 |
| TC-SCR-007 | HTTP 4xx/5xx | 게시판 실패를 기록하고 다른 게시판은 계속 처리한다 |
| TC-SCR-008 | 조회수의 쉼표 포함 값 | 숫자로 정상 변환된다 |
| TC-SCR-009 | 새 공지 1건 | 공지 1건과 outbox 1건이 생성된다 |

## 스케줄러와 동시성

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| TC-JOB-001 | 10분 주기 실행 | 수집 함수가 한 번 실행된다 |
| TC-JOB-002 | 같은 실행이 겹침 | 하나만 처리하고 중복 저장하지 않는다 |
| TC-JOB-003 | 수집 중 타임아웃 | 실패를 기록하고 기존 데이터는 유지한다 |

## 알림

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| TC-NOT-001 | 활성 게시판의 새 공지 | 해당 디바이스 outbox가 생성된다 |
| TC-NOT-002 | 비활성 게시판의 새 공지 | 해당 디바이스에는 outbox가 생성되지 않는다 |
| TC-NOT-003 | 같은 공지 재시도 | 동일 디바이스에 중복 발송하지 않는다 |
| TC-NOT-004 | FCM 일시 실패 | 제한된 횟수로 재시도하고 상태를 기록한다 |
| TC-NOT-005 | 만료된 FCM 토큰 | 토큰을 비활성화한다 |

## 앱 API

| ID | 시나리오 | 기대 결과 |
|---|---|---|
| TC-API-001 | 유효한 디바이스 등록 | 토큰이 등록·갱신된다 |
| TC-API-002 | 빈 device_id 또는 token | 400 오류가 반환된다 |
| TC-API-003 | 알림 설정 저장 | 게시판별 설정이 저장된다 |
| TC-API-004 | 공지 목록 cursor 조회 | 중복 없는 다음 페이지가 반환된다 |
| TC-API-005 | 존재하지 않는 공지 조회 | 404 오류가 반환된다 |

## 보안

| ID | 시나리오 | 기대 결과 |

## 수동 확인

- Android 13 이상에서 알림 권한 거부·허용 동작
- FCM 백그라운드 수신
- 알림 탭 시 공지 URL 열기
- 앱 재설치 후 새 디바이스 토큰 등록
