## 3. 콘텐츠 등급과 심사 접근 안내

현재 앱에는 이용자의 글쓰기·댓글·채팅·사진 업로드·사용자 간 공유·구매·도박 기능이 없다. 공개된 학교 공지 제목·작성자·날짜·조회수·원문 링크를 표시한다. 앱 안에서 임의 URL을 입력해 웹을 탐색하는 기능은 없으며 학교 원문은 외부 브라우저로 연다. 다만 공지에 포함되는 내용은 외부 편집자에 의해 갱신되므로 설문의 웹 콘텐츠·콘텐츠 교환·폭력·성적/약물·광고 관련 질문은 문구별로 실제 노출 범위를 확인한다. '우리 앱 사용자가 글을 쓰지 않음'만으로 모든 외부 콘텐츠 질문을 부정하지 않는다.

심사 접근 설명란에 사용할 문구:

> 회원가입·로그인·유료 구독·학교 계정 인증이 필요하지 않습니다. 앱을 열면 공지사항을 조회할 수 있습니다. Android 알림 권한을 거부해도 목록·검색·원문 열람이 가능합니다. 게시판 옆 종 버튼으로 알림을 구독하고 일반 공지의 별표로 저장합니다. 메뉴 → 설정에서 개인정보처리방침·이용약관·삭제 안내를 오프라인으로 볼 수 있습니다. 공지 원문은 동서대학교 공개 웹사이트를 외부 브라우저로 엽니다. 이 앱은 개인 개발 비공식 앱입니다.

- **공유**: Supabase·Google이 운영자를 대신해 계약에 따라 처리하는 서비스 제공자에 해당하면 Play 데이터 보안의 공유 예외가 적용될 수 있으므로 '제3자 공유 없음'으로 답할 수 있다. 개인정보처리방침의 처리위탁 공개를 생략한다는 뜻은 아니다. 공급업체가 독립 목적으로 이용하거나 추가 SDK를 붙이면 재판단한다.
- **전송 중 암호화**: 앱 API와 FCM은 HTTPS/TLS 사용, Android cleartext 차단. '예'로 입력한다.
- **계정 생성**: 허용하지 않음. Google·이메일·휴대전화 로그인 없음. 설치 등록을 회원가입으로 표시하지 않는다.
- **데이터 삭제 요청 제공**: '예'. 앱 설정의 이메일 요청 양식과 `/legal/deletion`을 제공하며, 운영자는 아래 7절의 실제 삭제 절차를 수행해야 한다. 즉시 앱 내 자동 삭제 기능이 있다고 표시하지 않는다.
- **정확한/대략적 위치**: 위치 권한·위치 API를 사용하지 않고 운영자가 IP로 위치를 추정하지 않음. 네트워크/보안상 IP 처리가 존재한다는 이유만으로 위치 서비스가 있다고 답하지 않는다. 공급업체 설정을 바꾸어 IP 기반 위치를 추출하면 다시 신고한다.
- **진단/충돌/분석**: Analytics·Crashlytics·Performance SDK가 없다. Firebase user agent에 버전·모델이 있다는 이유만으로 존재하지 않는 분석/성능 기능을 신고하지 않는다. FCM·플랫폼 서비스 로그의 실제 내용은 공식 Firebase 공개 문서와 Console 데이터 유형 정의를 대조한다. 기기 식별자 신고는 생략하지 않는다.
- **독립 보안 검토/가족 정책 인증**: 수행·취득하지 않았으므로 그렇다고 표시하지 않는다.

## 6. 비공개 테스트 제출 순서

1. 정책 원본·공개 URL·앱 내 내용·개발자 표시명·지원 이메일을 대조한다. 아래 법적/운영 확인 항목도 끝낸다.
2. 신규 제출 기준인 API 36+, 서명된 AAB, 16KB 메모리 페이지 호환성, 증가한 versionCode를 확인한다. APK는 개인 설치용, Play 업로드는 AAB를 사용한다.
3. Play 앱 서명을 설정한다. 기존 개인 APK를 덮어 업데이트해야 한다면 Play 배포 APK의 서명 인증서가 기존 인증서와 일치하는지 먼저 결정·확인한다. Google이 새 키를 만들면 기존 개인 APK와 서명이 달라 덮어 설치할 수 없다. 업로드 키와 최종 앱 서명 키는 다른 개념이다. 키 선택을 확인하기 전 기존 앱을 삭제하지 않는다.
4. 앱 콘텐츠와 스토어 등록정보를 저장한다. 비공개 테스트에서도 요구되는 정책·데이터 보안·건강 선언 등을 완료한다.
5. 테스트 및 출시 → 테스트 → 비공개 테스트에서 트랙 생성, 실제 참여자 Google 이메일 목록 또는 Google 그룹 등록, 지원 국가/지역 선택, AAB 업로드, 한국어 출시 노트 입력.
6. 검토 대상으로 변경사항을 전송하고 승인·트랙 게시 상태를 확인한다. 초대 링크로 참여자가 테스트 참여를 수락하고 같은 Google 계정으로 Play에서 설치한다. 링크만 보내거나 APK만 직접 배포한 것을 Play 테스트 참여로 계산하지 않는다.
7. 신규 개인 개발자 계정(2023-11-13 이후 생성)은 원칙적으로 최소 **12명이 연속 14일** 참여한 비공개 테스트 후 프로덕션 액세스를 신청한다. 계정 대시보드의 실제 조건을 우선 확인한다. 중도 탈퇴 후 재참여는 연속 기간이 다시 계산될 수 있다.
8. 실제 사용·피드백과 수정 내역을 기록한다. 12명/14일 충족만으로 프로덕션 승인이 자동 보장되지 않는다. 요구되는 테스트 설명과 출시 준비 답변을 실제 증거로 작성한다.
9. 사전 출시 보고서의 충돌·ANR·접근성·보안 문제를 확인하고 Android 알림 허용/거부, 일반/큰 글자, 검색·구독·별표·정책 오프라인·원문 열기·FCM foreground/background/종료 상태를 실제 기기에서 확인한다.

출시 노트 예시:

> 동서알리미 비공개 테스트 버전입니다. 대학 공지 조회·검색·저장·게시판 알림을 확인할 수 있습니다. 설정에 개인정보처리방침·이용약관·데이터 삭제 안내를 추가했습니다.

## 7. 운영자가 수행할 데이터 삭제 절차

이메일 양식은 요청 수단이며 자동 삭제 API가 아니다. 기존 `DELETE /devices/{id}`는 `active=false`만 설정하므로 개인정보 삭제 완료로 안내하면 안 된다.

1. 요청의 설치 ID를 식별한다. 이메일 주소와 설치 ID만으로 소유가 증명되지는 않는다. 등록된 기기에서 특정 게시판 구독 설정을 변경하도록 요청하는 등 해당 기기 제어를 확인하고 서버 결과와 대조한다. 확인 중에는 최소한의 정보만 취급하고 비밀값·FCM 토큰·신분증을 요구하지 않는다.
2. 등록을 다시 만들지 않도록 요청자가 앱 사용을 멈추고 알림을 끄게 안내한다. 확인 후 대상 `device_id` 한 행만 삭제한다. 예시는 관리자 SQL Editor에서 매개변수를 확인하고 트랜잭션으로 실행한다. 다른 기기나 전체 테이블을 삭제하지 않는다.

```sql
begin;
-- <VERIFIED_DEVICE_ID>는 소유가 확인된 요청의 ID로만 치환한다.
select device_id from public.devices
where device_id = '<VERIFIED_DEVICE_ID>' for update;
delete from public.devices
where device_id = '<VERIFIED_DEVICE_ID>' returning device_id;
-- FK ON DELETE CASCADE로 notification_preferences,
-- notice_alarm_preferences, notification_outbox가 함께 삭제된다.
commit;
```

3. 삭제 결과와 연결 테이블 잔존을 확인한다. 실행 중 발송이 이미 FCM에 넘어갔으면 회수가 보장되지 않음을 안내한다. 법적 보존 의무·서비스 제공업체 로그/백업/Firebase 설치 ID의 별도 보유 절차를 정책대로 설명한다. 서버의 기기 행 삭제가 Google의 FID 삭제 API 호출과 동일하다고 주장하지 않는다.
4. 확인 후 원칙적으로 7일 이내 처리·결과 회신 또는 지연 사유 안내. 문의는 처리 완료 후 1년 이내 삭제한다. 서비스 종료 때도 동일한 데이터 파기 의무를 관리한다. 정책에 쓴 보유·삭제 약속은 실제 운영 일정에 반영한다.

## 8. 정책을 갱신하고 다시 빌드하는 방법

원본: `frontend/assets/legal/policies.json`. 이메일·운영자·시행일·본문을 수정한 뒤 다음을 실행한다.

```bash
python3 scripts/sync-legal-documents.py
python3 scripts/sync-legal-documents.py --check
npx deno test --no-lock backend/__TEST__/edge/legal_test.ts
cd frontend
flutter test
flutter analyze
```

`supabase/functions/legal/documents.json`은 생성본이다. 공개 내용이 변경되면 **legal 함수만** 운영 프로젝트에 재배포하고 세 URL의 HTTP 200·본문·비로그인 접근을 확인한다. 서버 비밀값을 앱 빌드에 넣지 않는다. 빌드에는 기존 절차대로 `SUPABASE_FUNCTIONS_URL`, `SUPABASE_ANON_KEY` 두 공개 값만 전달한다. 앱 asset 갱신은 새 앱 버전 배포가 필요하다.

## 9. 제출 전 운영·법적 확인 사항

- 실제 문의 이메일 수신, 운영자 표시명과 Console의 일치, 7일 처리·문의 1년 보유를 실행할 수 있는지 확인한다.
- Supabase DB 지역은 Management API로 싱가포르를 확인했지만 전 세계 Edge·관리·보안 로그와 재수탁자는 별도다. Google도 글로벌 처리한다. 운영자가 DPA·국외 이전의 적용 법적 근거·고지의 충분성·실제 로그/백업 보관 설정을 확인해야 한다. 정책 문서 작성만으로 모든 법적 검토를 완료했다고 주장하지 않는다.
- 학교 공개 게시판의 수집·표시 허용 범위, 사이트 이용약관·robots·저작권·학교 이름/로고 사용 권한을 확인한다. 공개 페이지라고 재배포 권리가 자동 부여되는 것은 아니다.
- 직접 초대한 비공개 테스터만 참여하도록 관리하되, 공개 개인정보처리방침 URL은 누구나 읽을 수 있게 유지한다. 운영 DB에 자동 테스트 토큰·가짜 공지를 넣지 않는다.
- Console의 법적 선언·신원·판매자 상태·국가 선택·출시 제출은 소유자가 실제 화면에서 확인한다. 테스트 참여자 확보와 Play 심사·프로덕션 승인은 앱 코드로 대신 완료할 수 없다.
